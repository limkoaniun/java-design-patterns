# 速查表 — 大话设计模式（作者的一页判断）

## 决策规则
- **变化才是触发点，而不是计划。** 不要第一天就做抽象；当*第二个*变化出现时，只对这一条变化轴做抽象（开放-封闭原则（OCP）："拒绝不成熟的抽象"）。从最简单的设计开始；商场收银程序正是随着需求一步步，逐渐长出了五个模式。
- **先问「什么在变？」，再问「用哪个模式？」** 算法 → 策略模式（Strategy）。具体类 → 工厂方法模式（Factory Method）/抽象工厂模式（Abstract Factory）。额外行为 → 装饰模式（Decorator）。接口不匹配 → 适配器模式（Adapter）。依赖状态的行为 → 状态模式（State）。两条变化轴 → 桥接模式（Bridge）。对固定结构的操作 → 访问者模式（Visitor）。
- **默认的创建路径：工厂方法模式。** 只有面对产品*族*时才转向抽象工厂模式；用简单工厂模式（Simple Factory） + 反射 + 配置文件来化解工厂类爆炸。
- **继承会泄露，合成能包含。** 如果子类必须了解父类内部，或者两处变化会让类的数量成倍增长，就改用对象合成（合成/聚合复用原则（CARP））。
- **让用户的业务规则远离界面，也远离 `main`。** 书中每个示例一开始都因为把显示、计算和控制混在一起而失败（单一职责原则（SRP））。
- **当接收者的集合可能变化时，绝不要让发送者认识接收者**：观察者模式（Observer，多个接收者）、命令模式（Command，队列/撤销）、职责链模式（Chain of Responsibility，由谁处理在运行时决定）、中介者模式（Mediator，对等对象之间的网状关系）。
- **当模式已经存在于库中时，就直接使用库**：`java.util.Iterator`、`Cloneable`。学习其结构，不要重新实现。（例外：`java.util.Observable` 已被弃用；请自己编写 `Subject` 接口。）

## 相似模式：按意图区分
| 易混淆的一对 | 形状相同，意图不同 |
|---|---|
| 策略 vs 状态 | 策略模式中由客户端选择策略；状态模式中状态对象自己切换，并且知道自己的后继 |
| 装饰 vs 代理 vs 适配器 | 装饰模式添加行为（接口相同）；代理模式（Proxy）控制访问（接口相同，只有一个真实主题）；适配器模式转换接口 |
| 桥接 vs 装饰 | 桥接模式预先分离两个维度；装饰模式在同一个维度上叠加行为 |
| 外观 vs 中介者 | 外观模式（Facade）是对子系统的单向简化；中介者模式协调双向的对等通信 |
| 简单工厂 vs 工厂方法 vs 抽象工厂 | 一个 `switch`；每个产品一个工厂；每个产品*族*一个工厂 |
| 模板方法 vs 策略 | 模板方法模式（Template Method）通过继承改变步骤；策略模式通过合成替换整个算法 |
| 命令 vs 职责链 | 命令模式把一个请求打包给一个接收者；职责链模式沿链传递请求，直到有人接受 |
| 组合 vs 装饰 | 两者都是递归包装；组合模式（Composite）为树建模，装饰模式为分层行为建模 |
| 建造者 vs 抽象工厂 | 建造者模式（Builder）按有序步骤构建后返回一个产品；抽象工厂模式立即返回一个产品系列 |
| 访问者 vs 解释器 | 访问者模式：元素固定，操作不断增加；解释器模式（Interpreter）：一套表达式文法 |

## 坏味道 → 模式
| 征兆 | 可能的修复 |
|---|---|
| 在多个方法中反复对类型或状态字段做 `switch`/`if` | 状态（状态字段）或策略/工厂（类型字段） |
| 每新增一个产品都要修改现有的工厂类 | 简单工厂 → 工厂方法 |
| 子类数量 = 品牌数 × 功能数 | 桥接 |
| 每种附加功能的搭配都有一个子类 | 装饰 |
| 类认识陌生人的陌生人（`a.getB().getC().do()`） | 迪米特法则：引入中介者/外观 |
| 一个方法超过一屏长（"方法过长是坏味道"） | 提炼为模板方法或状态 |
| 带有细微差异的复制粘贴代码（"重复=易错+难改"） | 模板方法 |
| 对象需要重置到先前的状态 | 备忘录（Memento） |
| 大量相同的重量级对象 | 享元（Flyweight，拆分内/外部状态） |
| 重复的构建步骤，有时会漏掉某一步 | 建造者配合 Director |
| 数据库/供应商变化时，两个模块都要修改 | 依赖倒转 + 抽象工厂 |

## 作者明确给出的阈值与默认做法
- 先画类图：当相互作用的类超过约 3 个时，编码之前先画 UML（ch01）。
- Java 中的单例：优先使用静态初始化；如果要延迟加载，就用带 `volatile` 的双重锁定，绝不要只做一次裸的 null 检查。
- 原型：只要某个字段是引用类型，就要明确决定用深复制还是浅复制。
- 组合：默认用透明方式，除非叶子被误用确实是个现实风险。
- 带反射的抽象工厂：把数据库/供应商名称放在配置文件里，而不是代码里。
- 观察者：让观察者成为接口，而不是抽象类，这样不相关的类也能订阅；主题要声明为接口类型，绝不要声明为具体的 `Boss`。

## 全书的演进阶梯（衡量“该走多远”的标尺）
1. 能工作的过程式代码 → 2. 封装成类（业务逻辑 vs 界面） → 3. 简单工厂 → 4. 策略 → 5. 装饰模式处理可叠加的规则 → 6. 工厂方法 → 7. 抽象工厂 + 反射 + 配置。停在能够吸收你实际所面对的变化的那一级台阶上。
