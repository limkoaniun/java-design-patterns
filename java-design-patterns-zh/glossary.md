# 术语表 — 大话设计模式

格式：**术语** — 定义（第N章）。模式定义为作者的 [DP] 原文。

**Abstract class / 抽象类** — 不能被实例化；包含共享实现以及子类必须重写的抽象方法；子类共享代码时使用（第0章）
**Abstract Factory / 抽象工厂** — 提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们具体的类（第15章）
**Adapter / 适配器** — 将一个类的接口转换成客户希望的另外一个接口，使原本接口不兼容的类可以一起工作（第17章）
**Aggregation / 聚合** — 弱「has-a」：A 包含 B，但 B 不是 A 的一部分；生命周期不同（大雁与雁群）（第22章）
**Bridge / 桥接** — 将抽象部分与它的实现部分分离，使它们都可以独立地变化（第22章）
**Builder / 建造者** — 将一个复杂对象的构建与它的表示分离，使得同样的构建过程可以创建不同的表示（第13章）
**CARP / 合成/聚合复用原则** — 尽量使用合成/聚合，尽量不要使用类继承（第22章）
**Chain of Responsibility / 职责链** — 使多个对象都有机会处理请求，从而避免请求的发送者和接收者之间的耦合关系；将对象连成链并沿链传递请求直到有对象处理它（第24章）
**Command / 命令** — 将一个请求封装为一个对象，从而可用不同的请求对客户进行参数化；对请求排队或记录请求日志，以及支持可撤销的操作（第23章）
**Composite / 组合** — 将对象组合成树形结构以表示"部分-整体"的层次结构，使用户对单个对象和组合对象的使用具有一致性（第19章）
**Composition / 合成（组合）** — 强「has-a」：部分与整体共享生命周期（大雁与翅膀）（第22章）
**Coupling / 耦合** — 一个例程依赖另一个例程的紧密程度；目标是小、直接、可见、灵活的联系（松耦合）（第1、29章）
**Decorator / 装饰** — 动态地给一个对象添加一些额外的职责，就增加功能来说，装饰模式比生成子类更为灵活（第6章）
**Deep copy / 深复制** — 同时复制被引用的对象，因此克隆体相互独立（第9章）
**Dependency Inversion / 依赖倒转原则 (DIP)** — 抽象不应该依赖细节，细节应该依赖于抽象；针对接口编程（第5章）
**Double-checked locking / 双重锁定** — 检查空值、加锁、再次检查空值的单例创建方式；需要 `volatile`（第21章）
**Double dispatch / 双分派** — 访问者技术：先 `accept(visitor)` 再 `visitor.visit(this)`，使操作同时取决于元素类型和访问者类型（第28章）
**Encapsulation / 封装** — 把字段隐藏在方法/属性之后；每个对象对自己负责（第0章）
**java.util.Observable** — JDK 的主题基类；省去 attach/detach/notify 代码，但已被弃用，且作为类会阻碍其他继承（第14章）
**Extrinsic state / 外部状态** — 享元的状态，随每次使用而变化，由客户端传入（第26章）
**Facade / 外观** — 为子系统中的一组接口提供一个一致的界面，定义了一个高层接口，使这一子系统更加容易使用（第12章）
**Factory Method / 工厂方法** — 定义一个用于创建对象的接口，让子类决定实例化哪一个类；使一个类的实例化延迟到其子类（第8章）
**Flyweight / 享元** — 运用共享技术有效地支持大量细粒度的对象（第26章）
**Inheritance / 继承** — 子类复用并扩展父类；「is-a」；父类细节泄漏给子类（第0、22章）
**Interface / 接口** — 没有实现的方法契约；用于跨越继承层次的能力（第0章）
**Interpreter / 解释器** — 给定一个语言，定义它的文法的一种表示，并定义一个解释器，使用该表示来解释语言中的句子（第27章）
**Intrinsic state / 内部状态** — 享元的状态，在多个上下文之间共享，存储在享元内部（第26章）
**Iterator / 迭代器** — 提供一种方法顺序访问一个聚合对象中各个元素，而又不暴露该对象的内部表示（第20章）
**Law of Demeter / 迪米特法则 (LoD, 最少知识原则)** — 如果两个类不必彼此直接通信，那么这两个类就不应当发生直接的相互作用（第11章）
**Liskov Substitution / 里氏代换原则 (LSP)** — 子类型必须能够替换掉它们的父类型（第5章）
**Mediator / 中介者** — 用一个中介对象来封装一系列的对象交互，使各对象不需要显式地相互引用，从而使其耦合松散（第25章）
**Memento / 备忘录** — 在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以便以后恢复（第18章）
**Observer / 观察者** — 定义了一种一对多的依赖关系，让多个观察者对象同时监听某一个主题对象；主题状态变化时通知所有观察者自动更新（第14章）
**Open-Closed / 开放-封闭原则 (OCP)** — 软件实体应该可以扩展，但是不可修改（第4章）
**Polymorphism / 多态** — 通过父类型使用的子类对象运行其自己的重写方法（第0章）
**Prototype / 原型** — 用原型实例指定创建对象的种类，并且通过复制这些原型创建新的对象（第9章）
**Proxy / 代理** — 为其他对象提供一种代理以控制对这个对象的访问（第7章）
**Refactoring / 重构** — 在不改变行为的前提下重新组织结构；本书引入每个模式的引擎（第0、1章）
**Shallow copy / 浅复制** — 复制值字段，共享被引用的对象（第9章）
**Simple Factory / 简单工厂** — 一个带 `switch` 的类，返回具体产品；不是 GoF 模式；扩展时违反开放-封闭原则（OCP）（第1章）
**Single Responsibility / 单一职责原则 (SRP)** — 就一个类而言，应该仅有一个引起它变化的原因（第3章）
**Singleton / 单例** — 保证一个类仅有一个实例，并提供一个访问它的全局访问点（第21章）
**State / 状态** — 当一个对象的内在状态改变时允许改变其行为，这个对象看起来像是改变了其类（第16章）
**Strategy / 策略** — 定义了算法家族，分别封装起来，让它们之间可以互相替换，此模式让算法的变化不会影响到使用算法的客户（第2章）
**Template Method / 模板方法** — 定义一个操作中的算法的骨架，而将一些步骤延迟到子类中，使子类可以不改变算法结构即可重定义某些特定步骤（第10章）
**Transparent vs safe Composite / 透明方式 vs 安全方式** — 叶子声明 add/remove（统一但不安全）vs 仅组合节点声明（安全但客户端必须区分）（第19章）
**UML class diagram / UML类图** — 类、接口、继承（空心三角实线）、实现（空心三角虚线）、关联（实线箭头）、聚合（空心菱形）、合成（实心菱形）、依赖（虚线箭头）的表示法（第1章）
**Visitor / 访问者** — 表示一个作用于某对象结构中的各元素的操作，可在不改变各元素的类的前提下定义作用于这些元素的新操作（第28章）
